### ImageTextSelector Verification Design

This document describes the unit-level verification strategy for `ImageTextSelector`, the shared policy
that ranks image text candidates and reports how confidently the chosen text describes a picture. It
also owns the auto-generated-name filter and the source-to-provenance projection every format backend
reuses.

#### Verification Approach

`ImageTextSelector` is verified in isolation through unit tests in `ImageTextSelectorTests.cs` under the
`Output` folder of `DemaConsulting.DocDown.Core.Tests`, with method names beginning with
`ImageTextSelector_`.

Nothing is mocked; the selector is a pure function, so each test constructs a set of candidates,
invokes the real `Select`, `IsAutoGeneratedName`, or `SourceName`, and asserts on the returned value.
This is the correct boundary because the unit has no collaborators — its entire value is the ranking,
filtering, and confidence decision, so exercising it directly is what proves it.

#### Test Environment

- **Framework**: xUnit v3 under the .NET SDK, targeting net8.0, net9.0, and net10.0
- **Inputs**: candidate sets and object names supplied by the test
- **Mocking**: none; the pure policy is exercised directly
- **Isolation**: each test is independent with no shared state

#### Acceptance Criteria

Per IEC 62304 §5.5.2, an `ImageTextSelector` unit test run passes when a higher-ranked source outranks
every lower one; when a nearby heading is chosen only ahead of the media name and marked contextual;
when the media name is chosen only as a last-resort fallback; when an auto-generated object name is
discarded so a weaker but honest source wins while a meaningful name is kept and marked descriptive;
when empty text is ignored, the chosen text is trimmed, and no candidate carrying text yields `null`;
and when every source projects to a distinct camelCase provenance string. Any ranking that lets a
weaker source win, any heading or media name marked descriptive, any placeholder name treated as a
description, or any guessed text where none was offered is a failure.

#### Test Scenarios

##### Candidates are ranked by source preference

**Tests**: `ImageTextSelector_Select_DescriptionPresent_OutranksWeakerSources`,
`ImageTextSelector_Select_MeaningfulPictureName_IsDescriptive`

Proves the most directly descriptive source wins regardless of the order candidates were supplied, and
that an authored source (and a meaningful object name) is marked `Descriptive`. Evidence for
`DocDownCore-Output-ImageTextSelector-RanksBySource`.

##### Confidence gates a heading and the media name

**Tests**: `ImageTextSelector_Select_OnlyHeadingAndUri_ChoosesHeadingAsContextual`,
`ImageTextSelector_Select_OnlyUri_ChoosesUriAsFallback`

Proves a nearby heading is chosen ahead of the media name but marked only `Contextual`, and the media
name is marked `Fallback`, so a caller can refuse to assert either as a description. Evidence for
`DocDownCore-Output-ImageTextSelector-GatesByConfidence`.

##### Auto-generated names are discarded, meaningful names kept

**Tests**: `ImageTextSelector_Select_AutoGeneratedPictureName_FallsThroughToNextSource`,
`ImageTextSelector_IsAutoGeneratedName_GenericNames_ReturnTrue`,
`ImageTextSelector_IsAutoGeneratedName_MeaningfulNames_ReturnFalse`

Proves a placeholder object name such as `Picture 1` is discarded so an honest source is chosen instead,
while a meaningful name — including one that merely ends in a number — is kept. Evidence for
`DocDownCore-Output-ImageTextSelector-FiltersAutoGeneratedNames`.

##### Empty text is ignored, the winner trimmed, and nothing invented

**Tests**: `ImageTextSelector_Select_NoUsableText_ReturnsNull`,
`ImageTextSelector_Select_PaddedText_IsTrimmed`

Proves empty and whitespace-only candidates never compete, the chosen text is trimmed, and a set with no
usable text yields `null` rather than a guess. Evidence for
`DocDownCore-Output-ImageTextSelector-IgnoresEmptyText`.

##### Every source projects to a distinct provenance name

**Test**: `ImageTextSelector_SourceName_EverySource_ProjectsDistinctCamelCase`

Proves each source maps to a non-empty, distinct, camelCase provenance string, so the recorded
provenance is stable and machine-comparable across formats. Evidence for
`DocDownCore-Output-ImageTextSelector-NamesProvenance`.

##### A null candidate sequence is rejected

**Test**: `ImageTextSelector_Select_NullCandidates_Throws`

Proves a null candidate sequence is rejected as a caller error. A defensive test with no linked
requirement.
