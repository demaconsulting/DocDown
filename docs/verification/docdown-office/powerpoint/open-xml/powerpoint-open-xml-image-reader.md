## PowerPointOpenXmlImageReader Verification Design

This document describes the unit-level verification strategy for `PowerPointOpenXmlImageReader`, which
resolves the deck's embedded images across slides, notes, layouts, and masters.

### Verification Approach

`PowerPointOpenXmlImageReader` carries no dedicated test class: its observable contract is what reaches the
model, so it is verified through `OpenXml/PowerPointOpenXmlReaderTests.cs` — which reads image decks and
asserts the resolved image and its slide association — and through the emitter scenarios in
`Markdown/PowerPointContentEmitterTests.cs` that render the inline links the reader produces. Both run in
`DemaConsulting.DocDown.Office.Tests` against decks generated by `TestData/PptxFixtures.cs`.

### Test Environment

- **Framework**: xUnit v3 under the .NET SDK, targeting net8.0, net9.0, and net10.0
- **Inputs**: PresentationML decks with a synthetic embedded image and an authored description; read from an
  in-memory stream
- **Filesystem**: none for the reader scenarios; a per-test `TempScratch` folder where an emitter scenario
  resolves links on disk
- **Mocking**: none; the SDK is exercised against real generated decks
- **Isolation**: each test builds its own deck

### Acceptance Criteria

Per IEC 62304 §5.5.2, a `PowerPointOpenXmlImageReader` unit test run passes when it yields a distinct
embedded image carrying its exact bytes, media type, and authored naming source; records the referring slide
in the image's referrer set; exposes the image as a per-slide reference keyed by the same part; and does not
flag a real slide picture as template furniture or a fabricated orphan. Any lost image, wrong bytes, missing
slide association, or misclassified provenance is a failure.

### Test Scenarios

#### An embedded image is resolved with its bytes and naming source

**Test**: `PowerPointOpenXmlReader_Read_DeckWithImage_ExtractsEmbeddedImage`

Proves the reader resolves a slide's embedded picture to an image part carrying its bytes, media type, and
the authored description as its naming source. Evidence for
`DocDownPowerPoint-OpenXml-PowerPointOpenXmlImageReader-YieldsEmbeddedImages`.

#### The referring slide is recorded and exposed inline

**Test**: `PowerPointOpenXmlReader_Read_DeckWithImage_RecordsSlideAssociation`

Proves the image records the slide that references it in its referrer set, is not flagged as template
furniture, and is exposed as a per-slide reference keyed by the same part URI for inline linking. Evidence
for `DocDownPowerPoint-OpenXml-PowerPointOpenXmlImageReader-RecordsSlideAssociation`.
